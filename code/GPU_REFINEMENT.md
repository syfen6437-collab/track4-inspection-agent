# 2026-10-13 GPU 识别改进实验

正式结果仍是历史 56.11 分基线。训练实验只读取公开训练图片，所有新输出保存在
`runs/`，不改写正式 `result/result.json`、赛事设计书或提交包。以下本地指标不代表
官方得分，也不能保证通过初赛。

## 显存分配

桌面应用仍占部分显存，因此新增独立配置 `config/qwen3-vl-4b-offload.json`。
它保持 BF16 权重和原有预测设置，GPU 权重预算为 6,144 MiB，并要求至少额外
1,536 MiB 空闲供激活和生成使用，合计启动门槛 7,680 MiB。预算不足直接拒绝加载；
命令行的显存门槛只能提高要求，不能绕过预算检查。未配置预算时，原有分配和
10,240 MiB 评测启动门槛不变。

这不是量化，也不是减少模型参数。Accelerate 在 GPU/CPU 间分配完整权重；
处理器和模型显式设置 `local_files_only=True`，不调用外部推理服务。没有关闭
其他应用、停止其他项目或升级模型依赖。保留激活空间仍不保证任意分辨率都不会
OOM，因此先跑小样本再扩大。

已完成 6 张冒烟测试：4 张桥梁、2 张轨道，10 个模型生成轮次均正常解析，
无 OOM。包含初次加载的累计耗时 217.536 秒，不能将此小样本速率当作全量
推理时间保证。报告：`runs/offload_smoke_20261013/report.json`。

## 识别改动

新增可选 `training_description_guidance`：桥梁最终分类及粗筛读取训练词典的
典型描述，补充“修补区域并不等于完好”和“水渍/析出物需与普通纹理区分”的
观察要求。每个候选标签最多两条、每条最多 96 个字符。不改变合法标签范围，
不照抄示例作为输出描述。留出评测只使用拟合子集重新生成的词典；整座留出桥、
选中轨道样本的描述及人工审核笔记不会进入提示。

新增可选 `track_atomic_checklist`：模型分别判断轨道病害原子项，返回 `selected`
数组，而不是只能选最显眼的一项。程序按照完整训练标签词典规范化组合顺序。
若没有完整对应组合，只选择由模型已观察到的原子项构成的最大合法子集；不增加
未被模型识别的病害。原始数组和 `dropped_atoms` 记录到内部输出日志，正式结果
仍仅包含赛事的七个字段。空数组、未知标签、非 JSON 不报告为合法模型输出。

这两个开关默认关闭。逐条比较 3,402 条训练元数据，新开关关闭时的分类和粗筛
提示与 Git 中的基线完全相同。没有按测试文件名、样本 ID 或测试答案指定标签。

## 成对试验

`training_evidence` 同时打开上述两个开关，桥梁和轨道分支互不影响；每一类的
报告分别与相同图片的 `baseline` 比较。单独开关对照名为 `bridge_descriptions`
和 `track_atoms`。首次试验固定使用不含新开关的 offload 基础配置。

```powershell
.\.venv\Scripts\python.exe -u -X utf8 code\evaluate_holdout.py `
  --config code\config\qwen3-vl-4b-offload.json `
  --bridge-group 范家坪1号大桥 --sample-size 24 `
  --variants baseline,training_evidence `
  --output runs\training_evidence_20261013\fanjaping.json
.\.venv\Scripts\python.exe -u -X utf8 code\evaluate_holdout.py `
  --config code\config\qwen3-vl-4b-offload.json `
  --bridge-group 青树湾1号大桥 --sample-size 24 `
  --variants baseline,training_evidence `
  --output runs\training_evidence_20261013\qingshuwan.json
```

已存在报告必须加 `--resume`；更换代码、配置、模型或输入后使用新目录，不能
修改旧报告哈希强行恢复。每张图保存真值、自动生成预测和原始响应；真值只用于
评估，不进入输入元数据。报告同时记录合法标签覆盖范围、标度、原子 Macro-F1、
原正确丢失与新增正确数，不能只看单一总准确率。

每折 17 张桥梁、7 张轨道，属于小样本试验，并不覆盖全部轨道标签或正常样本。
需按独立图片数检查不同折间重叠，不能将两折轨道项直接当作 14 张独立证据。
有收益也必须进一步扩大整桥、正常样本和全部组合标签的验证，再生成隔离测试
候选。程序不会自动推广、上传或开始测评。

### 局部视觉特征对照

沿用现有开源 SigLIP2 和监督分类头，新增 `views=quadrants` 特征：每张图片
编码一次整图和四个重叠象限，分别保留整图、象限均值、象限逐维最大值，再融合
为归一化向量。原子监督头只用拟合轨道标签，桥梁仍用 k=5 近邻头，不训练新大模型。
每个局部图由同一个 224 像素视觉模型编码，但覆盖的原图区域更小；这不是凭空
补出原图不存在的细节。旧 `global` 模式及旧 CPU 特征缓存保持兼容。

特征缓存绑定模型、设备、视图和浮点精度。对照双方使用同一 GPU、FP32 精度、
相同原始训练记录和相同留出样本，只有输入视图/特征融合改变。缓存可以包含
留出图的无标签特征，但它们不会参与分类头拟合；整个桥梁分组均被排除。
不删除未见类别或难例来提高指标。两折各 84 张桥梁和 36 张轨道；轨道两折
共享 12 张，不能宣称为 72 张独立轨道图。先前像素内容审计确认这两个 120 张
留出划分均无拟合/评测的完全相同内容交叉。

```powershell
.\.venv\Scripts\python.exe -u -X utf8 code\evaluate_vision_heads.py `
  --device cuda --precision float32 --views quadrants --batch-size 8 `
  --bridge-method knn --sample-size 120 `
  --output runs\multiview_heads_20261013\quadrants.json
.\.venv\Scripts\python.exe -u -X utf8 code\evaluate_vision_heads.py `
  --device cuda --precision float32 --views global --batch-size 8 `
  --bridge-method knn --sample-size 120 `
  --output runs\multiview_heads_20261013\global.json
```

这些分类头报告不是赛事七字段结果，不生成模型描述，也不验证分级能力；不能
直接上传。局部特征已通过 4 张 GPU 冒烟，完整成对指标以完成的报告为准。

另外，`compare_visual_views.py` 使用两座桥的全部训练图片，轨道则按路径排序
后以固定种子随机留出 240 张，不依据标签挑样本。轨道只统计一次，不重复计作
两个折。运行前核对原训练内容审计、逐图文件哈希及完整像素的拟合/查询交叉；
两种缓存的模型、设备和精度必须一致。此检查不启动视觉模型或 Qwen，只读取
上述完整特征并在各拟合子集重新学习分类头。

```powershell
.\.venv\Scripts\python.exe -u -X utf8 code\compare_visual_views.py `
  --global-cache models\siglip2_train_features_cuda_fp32.npz `
  --quadrants-cache models\siglip2_train_features_cuda_quadrants_fp32.npz `
  --track-size 240 --seed 20261013 `
  --output runs\multiview_heads_20261013\natural.json
```

全桥图片仍含相关连续帧与原标注歧义；自然分布检查更接近公开训练数据的比例，
不保证等于隐藏测试集。模型没有生成描述或标度，因此报告删去评分准确率，
不能把空字符串相同解释成分级能力。观察到任何类别退步都应保持候选隔离。

分层成对实测（桥梁近邻头 / 轨道原子头）：

## 轨道小规模视觉微调

`train_track_adapter.py` 复用同一开源视觉模型，只更新最后两层编码器、输出
归一化/池化层及原子分类头，其余权重冻结。这不是 Qwen 大模型 LoRA。
固定随机留出 240 张轨道图，再从其余 560 张中随机选 100 张作模型选择验证，
460 张用于梯度训练。两个划分均不看标签挑样本，并核对像素内容隔离。

原子头从同一 460 张的冻结特征监督头初始化；冻结对照和微调后模型都在
相同 GPU、FP32、图片、处理器和标签空间上预测。只按内部 100 张验证的
Macro-F1 选择轮次，最多 8 轮。若没有轮次超过冻结基线，就选择第 0 轮。
外层 240 张的标签只在选定轮次后计算指标，不用于早停或更改训练参数。

```powershell
.\.venv\Scripts\python.exe -u -X utf8 code\train_track_adapter.py `
  --output runs\track_adapter_20261013\report.json
```

日志记录每轮损失、内部验证指标、完整外层对照、图片划分和来源哈希；只在
`runs/` 保存训练出的局部权重。它不生成描述或标度、不读取初赛测试图片。
这项试验尚无正式推理集成，也没有自动推广或上传功能。中断时保留已有轮次
报告，但当前训练入口不支持状态恢复；重跑应使用新目录，不照改旧断点。

两次预设参数相同、随机划分不同的试验均完成，选中轮次分别为 1 和 6：

| 外层随机划分 | 冻结头精确匹配 | 微调精确匹配 | 冻结 / 微调原子 Macro-F1 | 新增正确 / 丢失原正确 |
| --- | ---: | ---: | ---: | ---: |
| seed 20261013 | 64/240 | 109/240 | 0.450708 / 0.507026 | 51 / 6 |
| seed 20261014 | 61/240 | 117/240 | 0.384097 / 0.506051 | 61 / 5 |

但非完好漏检分别从 4 增至 16、6 增至 34；完好误报分别从 21 降至 17、
33 降至 21。收益主要来自单项病害分类，部分组合病害仍然困难，不能因为精确
匹配提高就称所有问题已解决。两折外层有 66 张相同图片，共 414 张不同图片，
不是 480 张独立验证图；两折拟合数据也来自同一公开轨道数据集。该结果只支持
继续研究视觉微调，不支持直接替换正式结果或推断官方得分。

两轮耗时分别为 144.599、154.393 秒，均含数据/模型哈希与预处理。只训练
21,268,998 个参数；每份保存的局部权重为 85,097,616 字节，位于各自的
`runs/track_adapter_20261013/` 与 `runs/track_adapter_20261014/`，不提交到 Git。
按验证集选择权重、最终评测及逐项预测全部由代码完成，没有人工覆盖输出。

`verify_track_adapter.py` 可重载保存的局部权重，重新对留出图推理，与保存的
自动预测逐项比较。它核对权重、基础模型、词典及训练清单，不执行训练，不读取
正式测试图，不覆盖正式结果；比较不一致会报错，不修改保存的预测来凑一致。

两份保存权重均完成全部 240 张外层预测的重载复验，所有标签与训练结束时
记录的预测一致。微调模型已验证可重新加载运行，但它仍是标签分类候选，
正式七字段输出和 56.11 分历史结果没有变化。全工程新增后通过 119 项自动测试。

```powershell
.\.venv\Scripts\python.exe -u -X utf8 code\verify_track_adapter.py `
  --report runs\track_adapter_20261013\report.json --sample-size 240 `
  --output runs\track_adapter_20261013\reload_check.json
```

## 性能对照

线程性能测试也使用配置对应的显存预算，而不是固定要求 10GB 空闲：

```powershell
.\.venv\Scripts\python.exe -u -X utf8 code\benchmark_inference_threads.py `
  --config code\config\qwen3-vl-4b-offload.json --threads 4 `
  --output runs\offload_threads_20261013\report.json
```

它在固定桥梁、轨道训练图片上按默认/4/4/默认顺序运行，检查完整预测和原始
响应是否一致。只有完成实测后才比较耗时；线程数不会根据某张图的真值选择。
